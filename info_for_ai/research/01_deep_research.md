# Deep and comprehensive research

## Activation

Use this module to investigate a topic, question, or controversy in depth and produce an evidence-led synthesis. When loaded as supporting research for another workflow, apply the method below but let the parent workflow own presentation under `00_core.md` supporting mode.

## Method

1. Decompose the question into decision-relevant subquestions. Bound the period and disciplines; for broad scopes, define a cutoff date and prioritize decisive subtopics.
2. Design searches using synonyms, technical terms, authors, and backward and forward citation tracing. Use reviews to map the field while tracing important claims to primary work.
3. Contrast findings across independent sources. Compare methods, assumptions, results, limitations, dates, and possible obsolescence.
4. Do not describe coverage as exhaustive beyond its declared scope. Record omitted fields, languages, periods, or databases that may bias the synthesis and surface them when material to the final result.

## Standalone output

Use this structure when deep research itself is the requested deliverable. In supporting mode, do not emit these sections merely because this module supplied the method.

### 1. Summary

Answer the question directly and state the level of consensus, main disagreements, search limitations, and cutoff date.

### 2. Thematic analysis

Organize by topic rather than discovery order. Each section must contain:

1. **Answer:** an integrated explanation separating evidence from interpretation.
2. **Sources:** verified, dated references and the version consulted.

Add **current importance** only when prioritization materially helps answer the request, and justify it from scientific impact, recency, evidence, and use rather than adding a label mechanically.

Add **research possibilities** only when the user asks for research directions or the evidence reveals concrete gaps, testable hypotheses, or next-step opportunities that materially improve the answer. State required data or methods and principal risks when included.

### 3. Additional sources

Include this section only when useful non-central reviews, data documentation, standards, software, conferences, or technical communication add material context. Explain why each is contextual rather than primary evidence.

### 4. Recommended reading path

Include a reading path only when the user asks to learn or study the topic, or when an ordered sequence materially improves navigation through the literature. When included, sequence an introduction or review, foundational work, recent results, and papers representing competing positions or methods as appropriate.
