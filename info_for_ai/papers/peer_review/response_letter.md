# Peer-review response letter

## Activation

Load this module when the task is to draft the submission-facing response to reviewers or editors after the relevant comments and manuscript changes have been assessed.

Use the parent `../01_peer_review_response.md` workflow for evidence discipline, repository boundaries, and shared inputs.

## Contract

Compare the submitted and current commits before drafting. Group the response by reviewer/editor and comment. Create a plain-text `.md` file only when the user requests a durable artifact, the parent workflow needs a submission-ready file, or continued work materially benefits from preserving it; otherwise return the response directly. When a file is created, do not use Markdown headings, lists, emphasis, tables, or other formatting in its content.

For each point, state what changed, where it changed in the manuscript, and any relevant code, experiment, table, figure, or supplementary artifact.

Keep the tone respectful, direct, and factual. Do not claim to have performed a change, experiment, validation, or correction that cannot be located in the current evidence. If an editorial request cannot be met, explain the precise limitation and the closest justified response.
